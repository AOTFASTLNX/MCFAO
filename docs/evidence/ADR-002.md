# ADR-002：Fabric0.19.3 构建期转换取证

日期：2026-11-08。A0/A1 PASS；B0/B1 PASS（仅第一方夹具范围）。

## 已固定的参考输入

A0来自用户启动的Minecraft26.1.2主菜单、该实例的Fabric0.19.3新日志，以及同一进程实际映射的Java25.0.1。进程同时打开该实例latest.log，已记录125个当前打开的JAR指纹。启动器为Swift Craft Launcher1.3.8(92)，实例和Java路径、Mod清单、GUI复现步骤均在artifacts/evidence/a0-desktop-reference/result.json。游戏参数由用户自己的启动器解析，未读取原始进程参数或凭据。

Fabric引擎七个依赖固定在compiler/fabric.lock.json：Loader0.19.3、Sponge Mixin0.17.3+mixin0.8.7、ASM9.10.1各组件。官方Loader源码归档SHA256为be9a8706ec13c886dd1b326fb4d1a5d7987e7883c63e39096f50db3ae8ac9ebc，仅下载和审读，不执行其Gradle构建。

## 源码核对与设计

- Knot.init依次设置真实GameProvider、发现/冻结Mod、加载ClassTweakers、引导Mixin、初始化转换器、解锁类路径并调用preLaunch。测试Bootstrap调用该方法后只执行第一方测试入口，不调用GameProvider.launch。
- getClassByteArray的true分支仍返回PreMixin字节。直接以此输出当成转换后结果会漏掉Mixin；因此采用第一方ClassFileTransformer，在Knot提交类定义时取最终字节，不修改其内容。
- MinecraftGameProvider仅对所选游戏命名空间应用访问修改。第一方Target放在net.minecraft.fabricaot_fixture包，避免在普通Mod命名空间测试而误判访问修改功能。
- Loader0.19.3的元数据仍使用accessWidener字段，其内容由ClassTweaker读取。本夹具只测试访问修改子集，命名空间固定official。

源码来源：[官方0.19.3源码归档](https://maven.fabricmc.net/net/fabricmc/fabric-loader/0.19.3/fabric-loader-0.19.3-sources.jar)，审读文件为Knot.java、KnotClassDelegate.java、FabricTransformer.java、MinecraftGameProvider.java、MappingConfiguration.java与V1ModMetadataParser.java。归档和运行库保留上游许可证；本项目的测试类独立编写。

## 实验合同

第一方fixture.jar含一个真实Inject Mixin、一个访问修改配置和嵌套JAR，父/嵌套Mod各注册main Entrypoint。行为必须同时满足mixedResult=42（原始为1）、原private字段转public且值7、两个入口各执行一次、嵌套资源可读。

参考阶段使用真实Fabric发现和转换；重放阶段只加载已导出的第一方字节码及固定入口列表，不引导Knot/Mixin。两者输出必须相同。原始未转换类必须明确因缺少Mixin结果而失败，其他启动失败不能替代这个负例。

运行前必须通过第一方沙盒控制，失败时不进入第三方初始化。默认拒绝策略的文件读/写与本地连接负例已实际通过，CPU/时间/单文件/文件描述符限制已启用。D0完整攻击面尚未验收。源码/输入指纹变化要求重新准备。

## 实际结果与证据链

- artifacts/b0/run-04/result.json：B0 PASS；沙盒控制、真实参考、重放及精确负例均通过。原始类SHA256为3bec137ceae0aad1319f8882e17fa15efcbe04c548b813f25902e66ef840b57f；转换后为1e65478fcc10c5c8f0bc774fa8d68fcc1b258d8b8e30f1d6fe08e826c2b5b389。
- 参考与重放均输出`B0_BEHAVIOR mixed=42 widened=7 parent=1 nested=1`。原始未转换类必须出现`AssertionError: real Mixin did not change result to 42`，不能以任意启动失败替代。
- 初始沙盒启动失败保留run-01/02/03与b0-startup-diagnostics摘要。最终策略允许根目录本身的读取、JDK UID初始化所需的两个精确mach服务；未允许主目录文件读取或通用socket连接。它仍不是完整D0认证。
- artifacts/b0/source-snapshot-04/保留B1所用B0版本的19个第一方输入；后续运行器修改要求新prepare目录，旧原始日志不覆盖。
- artifacts/b1/ios-probe-03/input-chain.json验证同一转换目标进入iOS AOT。构建classpath没有Minecraft游戏JAR；B1运行时不再加载Knot、Mixin或Java agent来定义新类。
- 自建运行库119翻译单元/6个archive的源码指纹与已验证A1一致，archive字节并非相同。新AOT对象和签名Framework分别保留。
- 用户在iPhone运行B1 build 4两次，create/run/teardown全部为0；两份原始日志均匹配B0行为并有B1_SEMANTICS_PASS。用户确认一次连接Xcode、一次未连接，不推断两张截图分别对应哪种连接状态。证据 artifacts/evidence/b1-user-device-run-01/。

B1 PASS只证明这个闭合的第一方夹具。固定入口重放尚不构成任意Mod静态编译器；ClassTweaker仅验证访问修改子集；Fabric API和现有53个Mod的iOS兼容性仍未知。Mac脚本由助手执行，真机由用户操作。完整复现见[B0](../B0_TEST_HANDOFF.md)、[B1](../B1_DEVICE_HANDOFF.md)。
