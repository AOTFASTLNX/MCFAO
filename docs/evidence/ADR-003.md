# ADR-003：真实客户端入口与原生调用诊断

日期：2026-11-08。**C0 BLOCKED，C1/C2 NOT RUN。** A0/A1/B0/B1已经各自验证；本记录不构成游戏启动或画面验收。

## 已读取的真实输入

用户本地合法客户端26.1.2，SHA256 b1b3158572666445eff01e82fad8c7de2e4953db6d354f311730d77a8359d0b0。只读使用A0已指纹化的共享依赖，未执行用户Mod、Gradle脚本或游戏Main，也未读取账户、令牌、玩家存档或游戏原始进程参数。

inventory_client_native_calls.py静态扫描10682个class文件，得到319个唯一LWJGL方法引用候选：OpenGL124、GLFW85、OpenAL35、system36、util26、STB6，以及PointerBuffer5、BufferUtils1、Version1。完整符号清单为 artifacts/evidence/client-native-call-inventory.json。这不是实际执行覆盖率；反射、JNI回调与动态解析可能增加依赖，尚无逐调用iOS测试。

因此仍需真实图形/窗口/音频适配。当前未选定可运行的Metal后端，没有将macOS原生库重标为iOS，也没有用3D测试图形代替真实Minecraft菜单。API版本、着色器语义、触摸输入、音频和逐调用测试还需随真实客户端引导完善。

## 真实入口可达性实验

probe_client_graph.py以net.minecraft.client.main.Main为分析根。Native Image25.0.2目标iOS arm64，使用本项目实际编译的iOS java/nio/net等静态库及固定版本数值CAP。只执行ExitAfterAnalysis；关闭工具链外部探测属于分析诊断配置，不能据此生成可分发游戏库。没有完成全客户端Fabric静态转换、资源闭包或JNI绑定。

每轮先用第一方程序证明工作区外文件读/写和本地socket连接受拒绝，再运行分析器。默认拒绝沙盒仅允许固定工具链、客户端/依赖JAR、iOS运行库，以及明确的clang路径；环境和写入目录独立。CPU/时间/输出/单文件/描述符受限，这仍不是完整D0认证。

## 复现

```bash
python3 -B tools/inventory_client_native_calls.py --output artifacts/evidence/client-native-call-inventory-new.json
python3 -B tools/probe_client_graph.py --output artifacts/c0/client-graph-new
```

输出目录必须不存在，且先有已确认的B1真机证据。参数--heap-gib支持6/8，--builder-gc支持parallel/g1；默认6 GiB/Parallel。每轮墙钟600秒/CPU1800秒，先检查主机/磁盘余量；8 GiB为当前18 GiB主机上限。本轮增加预算和改GC均未完成分析。失败记录必须保留，不以预算耗尽代替语义不兼容结论。

## 诊断范围与下一门槛

25个显式classpath内置元数据文件共124655字节，含542条反射声明、26条JNI声明、4条资源包含声明。没有发现Preserve=all或全资源通配；216个反射批量成员标志按具体类型注册，不等于全classpath保留。声明数不是实际可达类型数。审计不覆盖SDK默认、Feature API代码注册或分析推导出的动态访问，尚不能认定反射范围与OOM无关。

09/10的输入指纹、CAP、默认拒绝策略及除输出路径/堆预算外的命令均由脚本核对一致。10/11明确只改变构建JVM GC选项；11构建器源码新增了GC参数分支，源码差异单独记录，不声称源码字节相同。主机内存负载没有强制保持一致。

三轮均无完整analysis_stats或build-output JSON，可达类型/方法规模仍UNKNOWN，不能以10682个输入class或542条反射声明代替。GC后占用与暂停数据说明所试预算无法满足当前分析；没有对象直方图/保留链证据，不能声称已定位具体内存持有者。下一步优先在有界、隔离条件下取得保留对象证据，再决定是否收窄已证实冗余的注册或采用更充足的Apple Silicon构建资源。

本实验仍是未经过完整Fabric转换的核心客户端诊断。产品构建必须依次完成Mod解析/依赖核验→隔离的Mixin/ClassTweaker转换→最终类快照、转换覆盖和动态定义拒绝→AOT分析→iOS代码生成/链接/签名→用户真机引导。B0/B1只证明第一方夹具，不代表全客户端闭包。未完整分析之前不推进元数据补齐验收、Metal开发或游戏可玩宣称。

官方依据：[Native Image构建输出与JSON生成条件](https://www.graalvm.org/jdk25/reference-manual/native-image/overview/BuildOutput/)、[封闭世界与动态类定义](https://www.graalvm.org/jdk25/reference-manual/native-image/metadata/)。诊断JFR影响由固定Graal提交的JfrFeature.isInConfiguration确认：构建JFR会同时启用目标JFR，PosixLibM随后需要额外CAP；不是Minecraft不兼容证明。
