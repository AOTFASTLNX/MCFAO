# ADR-009: GL41/Zink primary renderer, native Metal retained

Date: 2026-11-15. Status: Accepted for integration; device gates remain BLOCKED until verified for this source and IPA. Supersedes ADR-008.

Minecraft Java 26.1.2 / Java 25 keeps its Blaze3D OpenGL backend. Calls pass through the statically generated LWJGL OpenGL JNI shim, OSMesa/Mesa Zink, MoltenVK, Apple Metal and the UIKit CAMetalLayer presentation surface. Game logic, rendering and saves execute locally on iOS ARM64 without Java JIT or a debugger.

The optional native Java MetalBackend and compiler/metal-backend remain available for regression and comparison. This is separate from GL41 using Metal for final presentation. GL41 must not require MetalBackend Java/JNI or translated vanilla shader artifacts. Renderer-specific inputs, fingerprints, staging and IPA checks must follow the selected mode.

## Acceptance

C0a requires the first frame from the real 26.1.2 client through GL41 on a physical device, with exact source, IPA digest and logs. C0b requires its real main menu and responsive input. A graphics probe or simulated menu does not pass either gate. C0c/C2 requires world interaction and save/restart/reload; E requires a measured 30-minute run. Vanilla results do not establish Fabric or Mod compatibility.

## Dependencies and limits

- Runtime bootstrap pins Amethyst-iOS commit 54d20f9a7b22c8cadc026cbad8eb1a386a1e6efe and exact OSMesa/MoltenVK binary digests in tools/fetch_gl41_runtime.py. This is binary provenance, not a verified upstream MoltenVK release number; extract/record actual runtime version during validation.
- OSMesa context support and Zink feature coverage depend on these exact binaries. Missing JNI/GL functions must fail explicitly; GL 4.5 DSA is not assumed on the 4.1 profile.
- Current presentation includes GPU to CPU readback and an intermediate Metal texture copy each frame. Triple buffering does not remove that bandwidth cost.
- GPU allocations, Java heap, jetsam and thermal throttling require physical-device measurement. Mesa Zink on Apple platforms remains experimental.
- Sodium, Sodium Extra and Iris require separate API and dynamic-class-generation validation; OpenGL availability alone does not make them AOT compatible.
- Historical world-join bypasses are experimental semantic changes and require gameplay regression; archived v14 measurements do not validate this integration.

## Reproducibility and safety

Preserve original GL41 source history, v14 tag, tests, failed experiments and provenance. Use an isolated integration worktree, task-specific outputs, immutable input/toolchain fingerprints and exact commit identity. Third-party Fabric transformations keep their existing sandbox; no unreviewed build scripts or initializers run in the personal host environment. Game assets and IPA stay private and local.
