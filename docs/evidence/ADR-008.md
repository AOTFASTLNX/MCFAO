# ADR-008：iOS 图形与窗口栈的替代方案

日期：2026-11-08。状态：**Superseded by ADR-009**（历史决策与实验保留）。执行计划见 [GRAPHICS_STACK_PLAN](../GRAPHICS_STACK_PLAN.md)。

本 ADR 承担 [TECHNICAL_GATES](../TECHNICAL_GATES.md) 中 ADR-003 要求的"Metal 路线（直接移植或兼容层）"决策部分；ADR-003 保留客户端入口与原生调用诊断记录。

## 背景

C0 在真机与模拟器上都已把 AOT 镜像执行到 `net.minecraft.client.main.Main.main` 之内（参数解析、log4j、291 项 Datafixer、JOML Unsafe 全部通过），随后稳定停在：

```
LinkageError: Unknown platform: iOS        (org.lwjgl.system.Platform.<clinit>)
→ 用 -Dos.name 绕过 →
UnsatisfiedLinkError: liblwjgl.dylib       (org.lwjgl.system.Library.loadSystem)
```

iOS 上没有 LWJGL 原生库，GLFW 也没有 iOS 后端。图形层不是"配一下"的问题，必须自己实现。

## 决策

采用**三层替换**，不移植 LWJGL 的 GL 绑定：

1. **窗口/输入**：第一方 `libglfw.dylib` 替身，实现客户端实际用到的 58个客户端C导出（另有Java辅助函数glfwFreeCallbacks）（含 3 个 Mojang 定制 IME 扩展与 1 个 LWJGL 的 `glfwGetCocoaWindow`）；LWJGL结构体访问器保留在Java/JNI层，内部是 UIKit + `CAMetalLayer`。
2. **渲染**：实现 blaze3d 已有的 `GpuBackend` 抽象（`MetalBackend` + `MetalDevice` + encoder/render pass），经 JNI 调 Metal。构建期用 ASM 在 `Minecraft` 的后端数组里追加该后端。
3. **着色器**：构建期把 88 个 GLSL 330 文件经 SPIR-V 翻译为 MSL，运行时按 id 查表，iOS 上不跑 translator。

核心依据：客户端的 OpenGL 引用 124 处**全部**位于 `com.mojang.blaze3d.opengl` 的 13 个类内，零泄漏到游戏逻辑；后端选择本身是一个 `GpuBackend[]` 回退循环。即"换后端"是官方设计内的动作，不是我们发明的旁路。

## 否证的备选

| 备选 | 否证理由 |
|---|---|
| `-Dos.name=Mac OS X` 伪装平台 | 只把 `LinkageError` 推后成 `UnsatisfiedLinkError`；`Platform` 静态初始化之后仍要真库。仅保留为诊断开关 |
| 把 macOS 的 LWJGL natives 改名当 iOS 用 | 架构是 x86_64/arm64-macOS，依赖 AppKit/OpenGL.framework，iOS 无这些；且违反"不把宿主库重标为目标平台"的既有规定 |
| GL→Metal 逐调用转译层（Zink + MoltenVK / ANGLE / MoltenGL） | 要多背一整条 GL 状态机 + GLSL 编译器；iOS 上 Vulkan 只有 MoltenVK 一条路，链路是 GLSL→SPIR-V→Vulkan→Metal，任一层出错都难定位。而本客户端已有后端抽象，可直接落到 Metal |
| GLFW 3.4 的 null platform | 无窗口、无输入、无呈现，`Window` 构造后拿不到 framebuffer 尺寸，问题只是后移 |
| 把渲染交给 MetalKit 的现成 Minecraft 移植 | 不存在这样的上游；自行重写渲染器等于换产品 |
| 用 SwiftUI/3D demo 顶替菜单 | AGENTS.md 硬约束，直接排除 |

## 后果

**正面**

- GL 依赖整体退出链接，不需要在 iOS 上提供 `libGLES`/`libGL` 兼容层。
- 后端失败路径是官方代码：`BackendCreationException` → 日志汇总 → `WindowInitFailed`，可观测性好。
- 着色器翻译在构建期完成，iOS 运行时不引入编译器，符合"无 JIT/无动态代码生成"约束。

**负面 / 代价**

- GLFW 替身必须是**行为等价**而不是符号占位：`Window` 对 `glfwGetWindowMonitor`／`glfwSetWindowMonitor` 的对称性、`GLFWErrorScope` 的错误码都有语义假设，只能靠第一方 C 夹具逐符号验证。
- Metal 后端要与 25 个顶层 GL 后端类对齐语义，最易出错处是 render pipeline state 缓存键、UBO/UTB 的偏移对齐、纹理格式映射。
- 构建期多一条 shader 工具链（glslang + SPIRV-Cross），需要版本锁定与逐文件产出清单。

## 合规与分发

- MSL 产物由用户本地客户端资源派生，**不入库、不进公开 IPA**；只提交翻译工具与清单格式。
- 不引入第三方 Minecraft 渲染代码；GLFW 替身是第一方源码，接口签名依 LWJGL/GLFW 公开 API 与客户端静态引用清单。
- 3 个 IME 扩展符号按客户端调用签名实现（`InputConstants`、`TextInputManager` 的静态引用），不从 Mojang 定制 GLFW 二进制反推实现。
