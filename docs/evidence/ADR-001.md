# ADR-001：Java 25 / iOS ARM64 AOT 实测

日期：2026-11-08。状态：**EXPERIMENTAL / A0与A1均PASS；后续B0状态见ADR-002**。

## 当前决策与结果

采用 GraalVM Community 25.0.2，将第一方 Java25 探针预编译为 ARM64 对象；用自行编写的构建入口，从固定的 OpenJDK/Graal 官方源码编译 iOS 静态库并链接 Framework。同一语义探针已在专用iOS ARM64模拟器和用户普通iPhone真实执行通过；iPhoneOS签名归档、本地IPA导出和嵌套签名也已核验。**用户明确确认build 2退出Xcode、拔线后重新打开仍PASS，变化日志名与全部断言已核对，A1 PASS。用户随后完成Mac Java25.0.1/Fabric0.19.3/26.1.2主菜单参考启动，A0也已PASS。**

原生代码和测试 App 均是本地研究成果。没有 Minecraft 游戏代码/资源进入 App，也没有执行用户整合包中的 Mod。

构建了146个明确终止的未提供 JVM 入口，以暴露不支持的原生调用。本次探针未触发它们；这不构成完整 Java 标准库或 Minecraft/Mod 兼容证明。线程、GC 和文件小负载结果也不等同于游戏世界/稳定性验收。

## 真机首次反馈与地址预留修订

用户通过 Xcode 安装并运行 build 1，截图中的 `a1-1794103237638.log` 与只读复制出的日志/JSON一致：createIsolate=801、run=-1、teardown=-1。上游 CEntryPointErrors 将801定义为 RESERVE_ADDRESS_SPACE_FAILED；本轮没有进入 Java 语义测试。

固定版本的 AddressRangeCommittedMemoryProvider 在未设置预留值时至少申请32 GiB虚拟地址空间。build 2 将 C isolate 参数的公开 version-1 字段 reserved_address_space_size 设为256 MiB；不访问内部保留字段，也不变更签名权限。用户真机已从801恢复为创建/执行/销毁全0，线程、ScopedValue、GC、资源、JNI、原子文件读写全部通过，且明确确认退出Xcode、拔线后独立重新打开。日志名从1794103907099变化为1794104082625，排除了只观看旧报告的歧义；后一运行段约0.024秒，仅描述这个小探针。

build 3修复冷启动先显示旧latest.json造成的反馈混淆：主线程先建立当前报告名，界面只读本进程报告；运行前显示RUNNING，STARTED与结束均更新UI。界面显示本次时间/耗时/日志，报告额外记录runID/processID，每进程仍只运行一次。用户随后提供了build 3 PASS截图（10:24:55.778，显示0.022秒）并已取得对应记录；A1独立运行依据仍明确指向build 2已确认的测试条件。UI扩展场景按用户分工继续测试，不以一次截图代替全覆盖。
