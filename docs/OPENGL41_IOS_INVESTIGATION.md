# OpenGL 4.1 renderer investigation (2026-11-14)

Status: **NOT IMPLEMENTED, NOT VALIDATED**. iOS does not expose desktop OpenGL 4.1 directly. An exploratory candidate is Mesa Zink (OpenGL to Vulkan) over MoltenVK (Vulkan to Metal); actual feature support depends on the driver and device. Mesa describes its macOS Zink path as experimental: https://docs.mesa3d.org/drivers/zink.html . MoltenVK documents iOS support: https://github.com/KhronosGroup/MoltenVK .

We examined the public Amethyst-iOS source at commit `54d20f9a7b22c8cadc026cbad8eb1a386a1e6efe`. Its Zink option uses an OSMesa bridge and presents a CPU-visible frame via a main-thread layer update. Its configuration sets `MESA_GL_VERSION_OVERRIDE=4.1`; this setting alone is not evidence that required functionality is implemented. Its bridge also calls `glFinish` for readback, so performance must be measured on device before adoption. Reference: https://github.com/Taylen27/Amethyst-iOS/tree/54d20f9a7b22c8cadc026cbad8eb1a386a1e6efe . No third-party code or binaries have been incorporated.

The user's exact hash-verified Sodium 0.8.11 and Iris 1.10.9 root JARs were scanned without executing their code using `tools/inventory_mod_opengl_calls.py`: 1,744 classes, 195 distinct LWJGL OpenGL method references. This is a conservative constant-pool inventory, not a runtime trace: it includes optional paths (including GL 4.3/4.6 and WGL references) and excludes nested JARs. Thus these references do not establish a minimum required GL version. Record and compare actual runtime coverage before declaring 4.1 compatible.

A real implementation needs, at minimum: an independently licensed and reproducible iOS Zink/MoltenVK build; a genuine GL 4.1 core context with required features verified without version/extension overrides; LWJGL JNI and function resolution; GLFW context and drawable integration; removal of Metal backend injection only for the alternate path; AOT compatibility with that path; then simulator and physical-device rendering and performance checks. The existing Sodium and exclusion safety gates must remain until this evidence exists. Fabric transformation currently independently excludes mods and libraries listed in `docs/RECOLLECTION3_CI_STATUS.md`; replacing the renderer will not automatically solve those exclusions.
