# 本地 IPA 构建工作台

Last reviewed: 2026-11-16

状态：Tauri 2 / React / TypeScript 实验版构建工具。工作台可直接启动本机完整构建与 IPA 导出；游戏的真机、整合包与性能 Gate 仍按 ACCEPTANCE.md 独立验收。

## 操作流程

1. **游戏内容**：选择或拖入 .mrpack / Prism 实例，运行静态检查；也可选择原版 26.1.2。当前 Fabric 构建器使用 Loader 0.19.3；来源声明不同版本时，可在来源卡片勾选「强制编译（忽略 Loader 版本差异）」继续。原包保持不变，实际使用的 Loader 版本写入任务记录与暂存清单。
2. **构建环境**：分发应用默认使用包内完整源码，开发模式也可选择 FabricAOT 源码目录；自动识别 artifacts/mcfao-local.json 或 mcfao.local.json。可选已有配置，也能在高级配置中逐项选择前置路径并保存独立 JSON。选择产物根目录后，每次构建会创建独立目录。
3. **开发签名**：可启用「导出未签名 IPA」，此时隐藏并跳过团队、证书、描述文件与 ExportOptions 检查，不执行 archive / exportArchive。未签名 IPA 不能直接装机，需另行签名。签名模式下 Team ID 可选，默认读取本机有效描述文件的团队；导出配置默认使用 ios/C0Harness/ExportOptions.plist。证书与私钥交由系统钥匙串和 Xcode 管理。
4. **确认构建**：Fabric 来源必须由使用者明确确认已审计构建期代码。点击「构建 IPA」实际运行 doctor、build，签名模式继续 export；不生成待用户复制执行的 shell 命令。

「构建记录」也支持选择含 result.json 的已完成 SIGNED_DEVICE_APP 目录（未签名模式选择 UNSIGNED_DEVICE_APP），重新核验原包，再执行归档、开发签名、IPA 导出及解包验签。此路径复用既有 AOT，不表示本次重新编译。


## 可配置存储与空间预检（2026-11-16）

设置页在「本地记录」上方提供「快速选择储存目录」：先确认覆盖，再选总目录；之后预览四类原目录、新目录、文件数和逻辑字节数，明确选择「迁移已有文件」「删除已有文件」或「保留原位」。未应用选择前不改设置，取消任一步均保留当前配置。

同一分组提供「重置目录设置」：确认后恢复当前源码/分发应用对应的四类默认目录，同步构建输出；只更新配置，不迁移或删除已有文件，原任务根仍保留用于历史发现。运行任务或环境变量固定目录时拒绝重置。

- 保留原位：只更新后续任务路径，已有文件不动。
- 迁移：新子目录须不存在，先复制到临时目录、检查目录结构并逐文件 SHA-256 校验；转换第一方 job.json / jobs/configs 内的目录引用。全部校验成功后切换配置，再清理原目录内容。IPA、签名产物、游戏内容、日志和输入指纹不重写，旧检查点可能需重新检测或编译；不保证所有历史缓存可直接复用。
- 删除：再次显示明确警告后才切换目录并删除四类原目录中的全部文件，包括 IPA 与任务记录。此功能不同于「空间清理」的产物保留规则。
- 处理时拒绝任务运行、环境变量路径覆盖、新旧路径相同或重叠、源码/家目录/卷根等非专用来源。预览指纹过期或复制/校验失败时保留原文件及设置；切换后若原文件变化或删除失败，保留该部分文件并显示提示。根目录与个人外接盘符号链接保留，不越过内部链接删除目标。
- 大目录操作须保持应用打开；迁移预检额外考虑复制量和构建空间预留，后端动作限时六小时。测试迁移/删除只在临时目录执行，没有自动处理本机用户文件。

侧边栏「存储管理」分别选择编译缓存、构建产物根目录、任务记录、Rust target 缓存。配置写入用户 Library/Application Support/NCL Builder 下的 storage.json；源码开发按项目路径隔离，包内源码使用 bundled 配置。支持 MCFAO_STORAGE_CONFIG 指定配置文件及 MCFAO_CACHE_DIR / MCFAO_BUILDS_DIR / MCFAO_JOBS_DIR / MCFAO_RUST_DIR 显式覆盖。选择 Rust 缓存只改变构建器的 target 产物位置，不迁移用户全局 Cargo/Rustup 安装与下载缓存。

存储管理页的普通「保存存储位置」只更新路径，不创建目标树、不移动或删除数据；旧任务根写入 previousJobRoots，历史任务、重试、日志与 Finder 定位继续使用原记录。运行中的构建或工具链准备会阻止更改位置；启动与设置写入通过同一控制锁串行化。源码仓库默认只做所选目录的空间预检；若本机存在未跟踪的 external-storage.json，则额外核验其中声明的链接，不能通过选择新路径跳过这部分守卫。分发应用不附带这份个人机器清单，改为检查所选卷与悬空链接。

构建前按物理文件系统合计预算：编译缓存 8 GiB、产物 24 GiB、任务 4 GiB、Rust 4 GiB，同盘需合计 40 GiB 空闲。这是最低预留，不保证大型整合包一定足够。CLI build、GUI 启动/重试/环境检查、桌面打包与首次下载均检查；空间不足会在创建构建输出前停止。

设置自定义位置后，「存储管理」只读统计四个目录，可在 Finder 中查看；自动清理保持禁用，不会沿用旧盘清理范围。

## 未签名 IPA 的校验

GUI 把 --unsigned 传给原 CLI。CLI 生成 UNSIGNED_DEVICE_APP / signature=UNSIGNED 后，工作台重验输入指纹、无 fallback 的可重定位 AOT 命令、arm64 iPhoneOS 链接目标、应用文件指纹及原生库/ABI，再逐条核对构建自带 IPA 与应用树的内容、CRC、大小及 SHA-256。IPA 必须位于本次构建目录内。完成页与确认页均明确标注未签名，不能直接装机；签名路径保留原有开发导出与验签。

## 应用源码与首次准备

Tauri 打包前通过 tools/bundle_source.py 生成受控源码树，覆盖 tools / compiler / interop / ios / tests / ci 及文档，放在 Contents/Resources/source。bundle-manifest.json 记录所有文件 SHA-256、源码提交与工作区差异指纹；构建前验证整棵源码树，脱离原开发机路径和 .git 仍可工作。缓存、产物、游戏 JAR、资源、存档、凭据和签名材料不进入应用包。旧交付包保留，新打包输出到所选产物根的 desktop/ncl-builder-<版本> 目录（已有同名交付时使用新的后缀）。

分发应用首次启动自动运行持久下载任务；设置页可看进度、错误及重试，关闭 UI 后任务继续。当前锁定下载清单为 **602,860,639 字节（574.9 MiB）**，包括 GraalVM 25.0.2、仅作数据保留的 iOS candidate ZIP、固定 OpenJDK/Graal 源码、图形工具源/运行库、STB、OpenAL 源码与全部五个 Maven ASM 依赖。实际量小于最初估计的约 1.1 GB；游戏文件另计。每次下载校验 HTTPS 源及重定向、字节上限、固定 SHA-256；失败的 .part 和日志保留，重试复用已校验文件。解包采用受限 data filter；此步骤不执行下载的 Gradle、CMake、configure、Mod 或构建脚本。

「我合法拥有 Minecraft Java Edition」每会话默认不勾选。明确确认后才允许从 Mojang 官方元数据、客户端、依赖和资源源下载；版本元数据及客户端/资源使用官方 SHA-1，Fabric 引擎使用仓库固定 SHA-256。仅保存客户端输入，不读取账户、密码或令牌，不执行游戏，不伪造 A0 PASS；所有权自我确认不等于微软账户资格认证。下载目录必须位于源码仓库外。生成 client-inputs.json 后可把该目录传给 prepare_b0.py --client-dir。

首次准备完成表示下载、校验与解包完成，**不表示全部 AOT 前置产物已编译**。仍需本机 ARM64 Python 3.11+、已选择且有 iPhoneOS SDK 的 Xcode，以及 BUILDING.md 所列 JNI 头文件、caps、运行库、桥接和配置。缺 Xcode 时界面、存储、下载与静态检查可用；真实 iOS 编译仍须明确报告所缺 SDK，不能伪造产物。AAR 缺失仅保留待登记请求，不阻断编译。

## 真实执行与持久任务

- Rust 仅允许固定 workbench 操作，使用参数数组启动第一方 tools/desktop_workbench.py，无 shell 文本执行。桌面宿主可以是 Intel，但 macOS 构建服务显式使用 ARM64 Python，避免 Rosetta 继承。
- supervisor 将 job.json、参数、输出与取消标记保存在所选任务记录目录的 <id>/ 下（源码开发默认 artifacts/desktop-jobs）。构建目录位于用户选择的产物根下。关闭 UI 后进程继续运行，重开工作台读取持久记录。
- 每个项目同时只允许一个任务。取消会终止任务的子进程树，包括原 CLI 新建会话的编译子进程；中断和失败保留日志。重试复用原始请求、暂存文件与构建路径，CLI 仍核对输入、参数和产物指纹才复用检查点。
- GUI 轮询阶段输出及嵌套编译日志，显示真实阶段，不伪造百分比。可导出当前日志快照，完整日志保留在任务目录；可分别在 Finder 定位 IPA 或任务文件夹。
- 只有 export 的 DEVELOPMENT_IPA_VERIFIED 结果、IPA 路径和 SHA-256 再次匹配后才显示「IPA 已验证」。不会由退出码 0 单独推断成功。

## 来源与资源边界

Prism 从 .minecraft、minecraft 或实例根选择真实 mods 目录；复制 mods、config、defaultconfigs、resourcepacks、shaderpacks、kubejs、scripts 白名单树。不会读取账户或复制玩家世界。拒绝树内符号链接。

.mrpack 先检查清单、路径、解压总量、碰撞等，再获取客户端 required 文件。server-only 与 optional 文件跳过并记日志。自动下载仅允许 HTTPS cdn.modrinth.com，使用 macOS 系统代理与 `*_proxy` 环境变量，TLS 证书和主机名继续校验；代理的 fake-IP 或本机解析结果不再被当作攻击拒绝。每次重定向重新校验域名。下载大小、SHA-1 / SHA-512 与清单逐个匹配。其他下载源或不支持的必要路径明确失败，建议通过 Prism 完成下载后导入本地实例。单文件上限 256 MiB，总暂存预算 4 GiB，最多 128 个根 Mod JAR。

覆盖文件依次应用 overrides、client-overrides，保存最终树 SHA-256。实际 JAR 再次静态检查，之后才交给原 CLI 的隔离转换流程。包配置和资源通过 --instance-data 进入输入指纹、Xcode instance-seed 资源及导出后校验。iOS 启动时仅补入不存在的包文件，保留已有用户配置；升级已有配置的迁移不在此实现。

Fabric 构建期转换发现静态 AOT 排除项时，任务会暂停并弹出确认：列明受影响的根 Mod 文件、不能转换的原因，以及依赖这些 Mod 的连带排除项。确认后从已校验暂存内容创建新副本，移除整份受影响根 JAR 和依赖项，再用新的构建目录重新运行转换；原始整合包、先前暂存与失败诊断都保留。取消会停止当前任务。若新一轮仍发现排除项，会再次征求确认，最多五轮。

用户确认只授权构建这个已明确缩减的子集，不会把被排除项目视为已转换或已验证。静态报告仍不能授予 `FUNCTION_PASS`；构建期隔离沿用现有受审计执行策略，D0 不因 UI 或下载检查而升级。

## 本机前置条件

- 完整构建使用 macOS Apple Silicon、ARM64 Python 3.11+、Xcode / iPhoneOS SDK，以及已有的 Java25 AOT、运行库、图形/音频和合法游戏资源配置。
- 工作台需要用户选择完整源码目录；应用包不包含游戏本体、工具链缓存、玩家账户或签名私钥。尚未实现新机器上一键从零准备全部原生前置输入。
- Windows / Linux 保留界面与静态报告能力，不能在本机执行 iOS AOT / 签名；远程 Mac 构建服务未实现。
- 开发包必须完成临时签名，否则 macOS 文件访问可能停滞。本地打包使用 npm run build:mac，脚本在 Tauri 打包后执行 ad-hoc 签名与严格验签；这不等于正式分发签名或公证。

## 外观

macOS 使用 Overlay 标题栏并隐藏原生标题文字，保留系统红黄绿按钮；侧栏延伸到窗口顶部，品牌区为系统按钮预留 64 pt，右侧顶栏与页面使用同一背景。侧栏顶部与右侧顶栏空白处可拖动窗口，主题按钮保持独立点击；顶栏在滚动时保持可见。窗口本身不滚动：滚动条属于顶栏下方的内容容器，因此从顶栏下沿开始、到窗口底边结束，而不是贯穿整个窗口高度；内容列仍以 1460 pt 为上限居中，窄窗口回落到 16–24 pt 内边距。低于 700 pt 时侧栏改为顶部横排，页面恢复整页滚动。默认居中打开为 1100 × 760 pt，最小 800 × 640 pt，仍可自由调整。

页面级操作以悬浮胶囊呈现，不随内容滚动：构建页顶部是步骤条胶囊、底部是「上一步 / 下一步 / 构建 IPA」胶囊；构建记录与环境与资源页的「新建构建 / 导出 IPA」「检测环境」胶囊固定在内容上方 8 pt 处，内容从其下方滚过。胶囊使用 `--raised` 底色、999 px 圆角和两级阴影，与内容区之间留出视觉间距。构建记录与环境与资源不再套外层卡片，改由分割线区分区域：环境与资源纵向排列，区域之间用 1 px 横向分割线；构建记录为两列，列表与详情之间用贯穿整列高度的 1 px 纵向分割线。

胶囊内部的控件同样是胶囊：步骤条里的每个步骤、底部栏的「上一步」与「下一步」、工具栏的按钮都使用 999 px 圆角，并在容器四边留相等内边距。几何上外层半径等于内层半径加内边距，所以两层曲率平行、看起来同心；任一方向的内边距不等都会让内层胶囊在视觉上偏离中心，因此移动端断点也保持内边距为正方形。底部栏的「上一步」与「下一步」等高，避免两个不同半径的胶囊并排。回归测试在浅 / 深色与 800 / 1100 / 1900 px 三种宽度下断言这条等式成立。

## 存储管理（2026-11-17）

侧边栏「存储管理」集中提供磁盘概览、文件分类分布、目录明细、清理预览及四类存储位置配置，设置页只保留其他偏好。首次进入自动只读扫描，也可重新扫描；大目录扫描期间可以切换页面等待。

- 按文件系统合并磁盘容量，以容量条区分 Builder 文件、其他已用与可用空间；点击磁盘筛选类别，点击类别查看最大的 12 个直接子项及大小，可在 Finder 中显示根目录或具体项目。
- `storage_inventory.py` 按 `st_blocks * 512` 统计已分配字节，嵌套根和硬链接只计一次，仅解析显式根目录链接，不展开内部链接。不可读/断盘目录显示提示，不创建目录或链接。APFS 共享块、快照与扫描期间变化可能导致占用与卷空间不同，不能将占用当作可释放空间。
- 旧布局继续扫描数据根下的 artifacts（包含历史 CLI 产物）及 cache / .cache、Rust target，任务根单独计数。清理候选分为编译缓存、Rust target、构建中间阶段和旧构建；后两组互不重叠，旧构建只清已知阶段目录并保留顶层日志和其他文件。
- 分组初始均不勾选；先展开路径明细、选择内容，弹窗确认后执行。清理后自动重新扫描分布。
- 永不删除 `result.json`、`inputs.json`、`job.json`、`checkpoint.json`、`.ipa` 与 `.xcarchive`；带 IPA 的构建目录整体跳过。
- 有构建任务在运行（`job.json` 状态为 running/queued/awaiting-exclusions 且进程仍存活）时拒绝清理。进程已退出的残留记录不阻止清理。
- `apply` 会重新计算计划，只删除本次计划内的路径；不跟随符号链接，路径必须位于数据根目录内。
- 实现：`desktop/src/StorageManager.tsx`、`tools/storage_inventory.py`、`tools/cleanup_storage.py`，工作台动作 `storage-plan` / `storage-clean`，原生 `reveal_path` 仅接收存在的绝对路径，通过固定参数调用 Finder。测试：`desktop/tests/storage-management.spec.ts`、`tests/test_storage_inventory.py`、`tests/test_cleanup_storage.py` 与工作台存储回归。

历史占用快照不作为当前容量或清理依据，须以重新扫描的结果为准。
